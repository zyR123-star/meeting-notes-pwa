# 多多速记

纯前端 PWA，用于课堂或会议的录音、转写、时间戳整理和 AI 笔记。课堂模式与会议模式共用同一套数据与录音能力，但使用不同的 AI 提示词。

## 运行

IndexedDB 在 `file://` 下会被浏览器拦截，不能双击 `index.html` 打开。请在项目目录启动静态服务器：

```powershell
python -m http.server 8080
```

然后访问 `http://localhost:8080/`。

## 功能

- 首页“会议 / 课程”双模式，按标题、正文、笔记和标签搜索。
- 课程卡包含颜色、老师、学期、课时数、加课时和编辑入口。
- 课时支持正文、自动分段录音、实时转写、时间戳目录和独立 AI 整理。
- 录音每 10 秒生成完整片段，先保存音频，再进入双并发 ASR 队列并按录音顺序追加字幕。
- 打点作为时间戳目录的折叠点；自动转写按相邻打点归入前一段，打点前内容归入“未标记”。
- 识别语言为 English 时，记录会保存英文内容标记，并使用英文 AI 小节与更稳健的长文本排版。
- 首页会议卡和课时行使用固定宽度的日期栏，日期、时长和状态在窄屏下保持对齐。
- 课程卡中的第几讲列表默认收起，可手动展开；搜索时自动展开匹配课程。
- 延续多多云朵与粉彩主题，在欢迎区和空状态加入少量 SVG 贴纸，避免重复装饰。
- 云朵、贴纸和空状态加入轻量漂浮动效，并尊重系统的减少动态效果设置。
- 提高云朵漂浮、爱心摆动和星星闪烁幅度，同时保持低频、低干扰。
- 详情页二级标题使用铅笔、麦克风、时钟和星星贴纸图标，形象对应且不使用动效。
- 会议与课程切换按钮分别使用对话气泡和笔记本贴纸，选中状态保持原有主色。
- AI 整理在录音和转写队列全部结束后由用户单独触发，不修改原始转写。
- 录音期间在支持的浏览器上申请屏幕常亮；PWA 进入后台时会停止录音，返回后不会冒充继续采集。
- 录音采用 48kHz 理想采样率和 192kbps 码率；转写遇到限流或临时服务错误会自动重试。
- MediaRecorder 每 10 秒自动切成新片段，每次切片都会新建 MediaRecorder；ASR 最多同时处理 2 段。
- 停止录音后立即恢复录音按钮；旧片段继续转写，新录音会追加到同一个有序队列。
- 字幕目录使用固定高度内部滚动；录音期间只展开最新字幕段，并仅在用户停留在底部时自动跟随。
- 音频按片段 `start` 顺序逐片播放，转写时统一加上片段起始偏移，点击时间戳会定位到对应录音片段。
- 设置页提供硅基流动、Groq、OpenAI 和自定义服务商预设。
- 支持 JSON 全量备份、恢复、单条 Markdown 导出和清理音频保留文字。

## AI 配置

- 转写：`POST {转写 Base URL}/audio/transcriptions`
- 笔记：`POST {笔记 Base URL}/chat/completions`
- 识别语言可选自动检测、中文或 English；自动检测时不发送语言参数。
- 转写优先请求时间戳，服务商不支持时自动回退普通 JSON；上传文件名会跟随录音格式。
- 硅基流动按官方文档仅发送 `file` 和 `model`，其他兼容服务可发送语言和时间戳参数。
- 硅基流动直接上传 2 分钟以内的原始录音片段，不再进行浏览器音频转码。
- AI 笔记会结合上下文修正明显的转写错误，并省略空内容、限制各节条目数量。
- AI 笔记按标题折叠，并提供“全部收起 / 全部展开”控制。
- 录音、语音草稿、转写和删除互斥；删除记录会停止语音草稿。
- 转写逐段保存，单段失败不会丢弃已经成功的结果。
- 备份不包含 API Key，逐条读取音频并分块生成文件，降低移动端内存峰值。
- 备份或恢复期间锁定首页导航、新建和编辑，避免数据在操作中途变化。
- 服务商必须允许浏览器跨域请求。
- 笔记 API Key 和转写 API Key 分开保存；转写 Key 为空时兼容旧版，回退使用笔记 Key。
- 课堂、会议和录音保存在 IndexedDB 数据库 `mtx`。

## iOS Safari

- 需要 HTTPS 或 `localhost` 才能稳定使用麦克风和 PWA。
- 录音时保持页面在前台，并建议关闭自动锁屏；iOS 息屏可能中断录音。
- 首次录音时请允许麦克风权限。
- 旧版应用需要联网重新打开一次，新 Service Worker 接管后会自动刷新。

## GitHub Pages 部署

1. 在仓库 `Settings > Pages` 中选择 `Deploy from a branch`，分支选 `main`、目录选 `/ (root)`。
2. 打开 `https://<用户名>.github.io/meeting-notes-pwa/`。

更新时直接提交到 `main`，GitHub Pages 自动重建。项目不使用 Release 或 Tag，提交历史和 `CHANGELOG.md` 共同作为更新记录。
